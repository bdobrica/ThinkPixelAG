# Recovery and resilience qualification

Production qualification uses an isolated PostgreSQL 18.4 instance and a
disposable Kubernetes cluster. Backup and WAL archives must be generated by the
same platform/version used in production; logical dumps alone do not prove PITR.

For each quarterly game day record timestamps, operators, image/database
versions, encrypted backup and WAL identifiers, recovery target, commands,
observed RTO/RPO, and the output of `scripts/check-restored-invariants.sql`.
Exercise full restore, PITR before and after a governance transaction, forward
schema recovery, DB failover and injected latency, OPA refusal/timeout/malformed
document, total Valkey loss, revocation stream partition/reconciliation, worker
termination, pod eviction, and rolling restart. The test passes only if no epoch
regresses, no committed evidence/outbox event disappears, no allocation expands,
and all authorization failure modes remain closed.

Provider-specific backup, failover, and fault-injection commands belong in the
environment overlay or controlled game-day record; the repository deliberately
does not make one cloud platform authoritative.
